# Narratiive Knowledge Types

## Purpose

This document defines how reusable knowledge is classified inside Narratiive OS.

Every file should primarily belong to one of four types:

1. Doctrine — what Narratiive believes.
2. Processes — how Narratiive works.
3. Templates — reusable blank starting points.
4. Examples — completed or client-specific work.

Supporting categories include Evidence, Archive and Working Material.

## Classification

| Location | Primary type | Purpose |
| --- | --- | --- |
| `knowledge/doctrine/` | Doctrine | Philosophy, strategic principles and durable context |
| `knowledge/handbook/` | Doctrine | Narratiive-owned strategic models and IP |
| `knowledge/blueprint/` | Doctrine / Canon | Locked Growth Blueprint source assets |
| `docs/` | Processes / Governance | Operating architecture, rules and methods |
| `agents/` | Processes | Specialist agent contracts |
| `workflows/` | Processes | Automation definitions |
| `templates/` | Templates | Blank reusable starting points |
| `clients/` | Examples | Client-specific state and material where permitted |
| `knowledge/research/` | Evidence | Source research supporting doctrine and decisions |
| `archive/` | Archive | Superseded material retained for reference |

## Rules

Before creating a reusable file, ask:

1. Is it a belief or strategic standard? Put it in Doctrine.
2. Is it an operating sequence? Put it in Processes.
3. Is it a blank reusable starting point? Put it in Templates.
4. Is it completed or client-specific work? Put it in Examples or the client workspace.
5. Is it source evidence? Keep it separate from the doctrine it supports.

Do not promote client examples into doctrine without an explicit canon decision. Do not duplicate product canon into general knowledge. Prefer references to the authoritative source.
