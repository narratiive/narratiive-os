# Narratiive OS Vision

## Purpose

Narratiive OS is a strategic growth operating system.

It exists to move client work from manual coordination and repeated prompt-pasting into supervised autonomous production, where strategy, creative direction, production workflows and delivery systems are reusable, inspectable and continuously improved.

The agency is the first application of the operating system. The long-term product is the operating system itself.

## Direction

Narratiive should operate as a connected system rather than a set of disconnected AI conversations.

The system should:

- Diagnose growth problems before recommending activity.
- Turn structured research into strategic clarity.
- Turn strategy into Campaign Worlds and Creative Director's Bibles.
- Turn approved creative systems into prompt packs, image assets, video assets, landing pages and client deliverables.
- Track every client through clear operational state.
- Preserve reusable knowledge in version control.
- Reduce manual administration without removing human judgement.

## Source of truth

GitHub is the source of truth for reusable knowledge, prompts, templates, workflows, agent protocols, frameworks, operating rules and version history.

No important strategic system should exist only in chat. If it is reusable, it belongs in this repository.

Notion is the operational state layer. Google Drive is the client-facing deliverable layer.

## Human and agent roles

Matt owns strategy, judgement, approvals and client relationships.

Tony is the orchestrator. Tony monitors state, interprets commands, routes work, triggers workflows, detects blockers, requests approvals and reports progress. Tony coordinates specialists but does not create strategy independently.

Codex is the engineering and repository operator.

Claude is the strategy and long-form thinking specialist.

## Operating model

1. Matt gives intent.
2. Tony identifies client state and next action.
3. Tony routes work to the correct specialist.
4. Specialists use repository knowledge instead of ad hoc prompts.
5. Outputs return to Tony for validation, state updates and approval routing.
6. Matt approves strategy and client-facing decisions.
7. Production systems create assets from approved source material.
8. Learnings return to the knowledge layer.

## Long-term goal

The goal is supervised autonomous production with versioned reusable knowledge, clear agent responsibilities, command-driven orchestration, structured client state, approved strategic source documents, repeatable production workflows and human approval at the right moments.

Autonomy should increase only where confidence, structure and approval gates are strong.
