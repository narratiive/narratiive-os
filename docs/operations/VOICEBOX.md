# Optional Voicebox service

Status: optional local integration; disabled by default

## Decision

Narratiive OS can use Voicebox as a separately managed voice-generation service
through `runtime.voicebox_service`. Voicebox is not vendored, installed, or
started by Narratiive OS, and it is not registered as a Tony, OpenClaw, n8n, or
workflow capability automatically.

This boundary is intentional. Voice generation may create client-facing output,
so the existing Narratiive evidence, workspace, lineage, quality-review, and
authorised-human approval gates still apply before audio is released, published,
sent, or used in production.

## Why the integration is limited

The reviewed Voicebox source is actively maintained and provides a FastAPI REST
API plus a FastMCP server. It supports multiple local engines, voice profiles,
asynchronous generation, status/history endpoints, and audio download. Its main
application and bundled Docker Compose configuration default to loopback access.

Voicebox does not currently authenticate its local REST or MCP routes. The
`X-Voicebox-Client-Id` header selects per-client preferences; it is not a secret
or an authentication control. Narratiive therefore rejects non-loopback HTTP
endpoints. A remote endpoint requires both an explicit opt-in and HTTPS, with
authentication and network policy supplied by an operator-managed reverse proxy.

## Install and run Voicebox

Choose one upstream installation method and follow the release instructions at
<https://github.com/jamiepine/voicebox>. Narratiive does not pin or download
Voicebox, Hugging Face models, Python packages, CUDA/ROCm wheels, or voice data.

For the desktop application, confirm the API is listening locally:

```bash
curl --fail http://127.0.0.1:17493/health
```

The upstream Docker Compose file maps the container service to
`127.0.0.1:17600`; when using that configuration, set the Narratiive URL to
`http://127.0.0.1:17600` instead.

Create a voice profile only from audio that Narratiive is authorised to use.
Keep reference recordings, cloned profiles, generated audio, the Voicebox
SQLite database, and model caches outside this repository.

## Configure Narratiive

Copy the variable names from `docs/operations/voicebox.env.example` into the
existing local mode-`0600` Narratiive environment file. Do not commit the local
file or any real profile names if they disclose a person or client.

At minimum:

```dotenv
NARRATIIVE_VOICEBOX_ENABLED=true
NARRATIIVE_VOICEBOX_URL=http://127.0.0.1:17493
NARRATIIVE_VOICEBOX_CLIENT_ID=narratiive-os
NARRATIIVE_VOICEBOX_PROFILE=approved-local-profile-name
NARRATIIVE_VOICEBOX_ENGINE=qwen
```

The integration is inert when `NARRATIIVE_VOICEBOX_ENABLED` is absent or false.
It has bounded request timeouts and response sizes. It never sends an upstream
API key because Voicebox has no corresponding authentication contract. For an
explicitly approved remote HTTPS reverse proxy, it can send
`NARRATIIVE_VOICEBOX_BEARER_TOKEN`; the proxy, not Voicebox, must enforce it.

## Python use

```python
import os

from runtime.voicebox_service import VoiceboxClient, VoiceboxConfig

client = VoiceboxClient(VoiceboxConfig.from_env(os.environ))
health = client.health()
profiles = client.list_profiles()
started = client.speak("Draft voice check. Do not distribute.")
completed = client.wait_for_generation(started["id"])
audio = client.download_audio(completed["id"])
```

The caller owns storage, lineage, approval checks, and delivery. Do not write
generated bytes into a client workspace or send them onwards without the normal
Narratiive object and approval records.

## n8n and OpenClaw

Voicebox can be called directly by n8n over its REST endpoints and exposes MCP
at `/mcp`. For Narratiive, direct connections should remain loopback-only and
must not bypass the authenticated Tony bridge or public command gateway for
business-state changes. A successful audio generation is tool output, not
workflow completion or approval.

No Tony or OpenClaw configuration is added by this change. If a future approved
workflow needs voice output, integrate this client behind the existing public
command boundary and record workspace/client identity, source text, profile and
engine identifiers, generation ID, output checksum, and the exact human
approval governing release.

## Model and hardware guidance

Engine quality and resource use vary materially:

- Qwen3-TTS 1.7B offers the strongest general multilingual cloning and delivery
  control in the current Voicebox stack, but is the heaviest normal default.
- Qwen3-TTS 0.6B and Chatterbox Turbo trade some capability for lower latency and
  memory demand.
- LuxTTS is positioned upstream as a lightweight English cloning engine; Kokoro
  is a small preset-voice engine rather than the main cloning choice.
- Chatterbox Multilingual covers the broadest language set; TADA targets longer
  coherent generations but its dependency stack is comparatively young.

Treat upstream hardware claims as guidance, not a Narratiive service-level
guarantee. Model downloads are large, first generation includes load time, CPU
operation can be slow, Apple Silicon uses MLX/Metal where supported, and NVIDIA
or AMD acceleration depends on the correct Voicebox build. Validate the chosen
engine, language, reference recording, latency, memory use, and long-script
chunking on the exact production machine before adopting it.

## Privacy, security, and responsible use

- Obtain explicit consent for each cloned person and permitted use case.
- Never clone public figures, clients, staff, or third parties by implication.
- Treat reference audio and generated speech as biometric/sensitive personal
  data with access control, retention, deletion, and incident handling.
- Do not expose port `17493` or `17600` to a LAN, VPN, tunnel, or the public
  internet without authentication and TLS in front of Voicebox.
- Disable Voicebox Cloud sync unless its separate terms, data flows, retention,
  and account controls have been approved for the relevant data.
- Review every generated take for pronunciation, hallucinated sounds, clipping,
  truncation, speaker similarity, and unintended emotion before approval.
- Preserve Voicebox's MIT notice if Narratiive later redistributes substantial
  portions of its source. Model weights and engine dependencies retain their own
  licences and acceptable-use terms; MIT licensing of the Voicebox application
  does not relicense them.

## Removal

Set `NARRATIIVE_VOICEBOX_ENABLED=false` or remove the variables. Narratiive has
no migration or stored service state to remove. Delete local voices, recordings,
models, and generations using the separately installed Voicebox application's
data-management process when required by consent or retention policy.
